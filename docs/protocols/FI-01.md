# FI-01 — Guardado y recuperación ante fallos

**Prioridad:** crítica · **Código:** `src/Trazo.Core/IO/ProjectSaver.cs` · **Pruebas:** `tests/Trazo.Core.Tests/FI01_PersistenceTests.cs` y `tests/Trazo.Rendering.Tests/LY01_LayerIntegrityTests.cs`

## Objetivo

Que una interrupción nunca destruya el último estado válido del documento.

## Diseño (transacción de guardado)

| Etapa | Acción | Si falla |
|---|---|---|
| 1. Serialize | Se genera el ZIP `.trazo` completo en memoria | No se toca el disco |
| 2. WriteTemporary | Se escribe en `obra.trazo.tmp` | Se borra el `.tmp` |
| 3. Flush | Se vuelca a disco (`FlushFileBuffers`) | Se borra el `.tmp` |
| 4. Verify | Se **relee** el `.tmp` y se compara capa por capa con lo que se quería guardar; se validan las cabeceras PNG y las dimensiones | Se borra el `.tmp` |
| 5. Replace | `File.Replace` atómico; la versión anterior queda como `obra.trazo.bak` | El original no cambia |

Cualquier fallo lanza `SaveFailedException` con la etapa y un mensaje como "No se pudo guardar. El archivo anterior sigue intacto.". La app lo muestra, mantiene el documento como pendiente de guardar y lo reintenta en el siguiente autoguardado.

**Al abrir:** primero se intenta el archivo principal; si falta o está dañado, la copia `.bak`; y por último el `.tmp` de un guardado interrumpido. Si se recupera desde una copia, el usuario recibe un aviso y el documento se vuelve a guardar sano.

## Fallos simulados

Las pruebas usan un sistema de archivos en memoria que falla a propósito, más pruebas con archivos reales en disco.

| Fallo | Etapa esperada | Resultado |
|---|---|---|
| El dispositivo deja de responder a mitad de la escritura | WriteTemporary | ✅ original intacto, sin `.tmp` |
| Disco lleno (`ERROR_DISK_FULL`) | WriteTemporary | ✅ mensaje específico de falta de espacio |
| Error de E/S al volcar | Flush | ✅ |
| Corrupción silenciosa de un byte de una capa | Verify | ✅ se detecta al releer |
| Destino bloqueado por otro programa (archivo real en disco) | Replace | ✅ |
| Archivo principal truncado (corte de luz) | — | ✅ se abre la copia `.bak` con aviso |
| Cierre inesperado antes de renombrar | — | ✅ se recupera el `.tmp` |
| Nada válido | — | ✅ error claro con el nombre del archivo |
| Capa de tamaño incorrecto o PNG inválido | Verify | ✅ |

## Límite de pérdida especificado

Con autoguardado a los **3 s** del último cambio, un cierre inesperado pierde como máximo los últimos 3 s de trabajo. **Pendiente:** una prueba que mate el proceso durante el guardado (por ejemplo, con `Process.Kill` desde un arnés externo) y compruebe la recuperación.

## Limitaciones

- La recuperación desde `.bak` devuelve la versión **anterior** al último guardado. Es correcto: es la última versión válida, pero puede faltar el trabajo más reciente, y el aviso lo dice.
- No hay historial de versiones múltiples, solo una copia anterior.
